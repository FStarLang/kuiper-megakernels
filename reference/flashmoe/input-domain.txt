FlashMoE capacity-drop router: valid input domain
=================================================

This is a plain-language statement of the inputs the reference (base.py) and
the proofs accept. It replaces an earlier source excerpt and has the same
meaning. It is a description, not a runnable module.

Case identifier: flashmoe_capacity_drop

Problem sizes (profiles)
  smoke profile: 256 tokens, hidden size 512, FFN size 1024, 8 experts,
                 per-expert capacity 32, top-k 1, tile height 128
  full profile:  1024 tokens, hidden size 5120, FFN size 8192, 16 experts,
                 per-expert capacity 64, top-k 1, tile height 128

Profile selection from the environment
  - RESOLVE_MEGA_CASE_ID, if set, must equal the case identifier above.
  - RESOLVE_MEGA_SMOKE must be "0" or "1" and defaults to "0".
    "1" selects the smoke profile; "0" selects the full profile.
  Anything else is rejected as an invalid workload.

Operands, for the selected profile
  - tokens: a tensor of shape [tokens, hidden].
  - router_weights: a tensor of shape [hidden, experts] (logical layout;
    see LAYOUT.md).
  - Both are torch.bfloat16 and contiguous.
  - Every element of both is finite (no NaN or infinity).
  - Magnitude bounds, inclusive: |tokens| <= 32 and |router_weights| <= 4.
  - Both are on the same device.
  Inputs violating any of these are rejected as an invalid workload; the
  reference makes no claim about them.
