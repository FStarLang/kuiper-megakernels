Profile, input domain and validation (LUCE RESOLVE run, smoke profile)

Workload: greedy BF16 decode of Qwen/Qwen3.5-0.8B (revision
2fc06364715b967f1860aea9cf38778875588b17), text model only, all 24 layers
(18 Gated DeltaNet "linear_attention" layers and 6 "full_attention" layers,
pattern 3 linear + 1 full, repeated 6 times), full original dimensions:
hidden 1024, MLP intermediate 3584, vocabulary 248320, full attention with
8 query heads / 2 KV heads of head_dim 256 (output gate, q/k RMSNorm, partial
rotary factor 0.25, rope_theta 1e7), DeltaNet with 16 key/value heads of
dimension 128 and a 4-tap causal depthwise convolution, rms_norm_eps 1e-6,
LM head tied to the embedding matrix. The exact numeric configuration is
model_config.json.txt (text_config) together with configuration_qwen3_5.py.

Roles:
- base: the pinned Hugging Face transformers 5.3.0 Qwen3.5 implementation
  (modeling_qwen3_5.py, eager attention, torch recurrent gated delta rule and
  torch causal conv1d update, no fused kernels), driven one token at a time
  by decode_reference in base.py. This is the reference semantics.
- optimized: the official Luce-Org/lucebox megakernel at commit 0f212ac
  (optimizations/megakernel; BF16 Qwen3.5-0.8B decode megakernel for H100
  sm_90, fast-math), decode path only, repetition penalty fixed at its default
  1.0. Its reduced CUDA program is inputs/optimized/program.cu.
Both roles have the same interface; see LAYOUT.md.

Inputs (one program call):
- packed_weights: contiguous BF16 vector of 752393024 elements holding the
  checkpoint's 320 text parameters in the order of LAYOUT.md. In every test
  it is the actual checkpoint, converted to BF16; it is an ordinary program
  input, not a constant.
- prompt_tokens: contiguous int64 vector of length P with 1 <= P <= 8 and
  every element in [0, 248320).
- decode_steps: an integer in {1, 5}.
Anything outside this domain is rejected by validate_inputs before either
role runs, so the specification may assume it. Positions used are
0 .. P + decode_steps - 2, far below the 2048-position cache bound.

Semantics: each call starts from fresh, all-zero state (attention KV cache,
DeltaNet recurrent state and convolution state). The prompt tokens are fed
one at a time at positions 0, 1, ...; the outputs for the first P-1 of them
are discarded. Then decode_steps steps are produced: each step feeds one
token (first the last prompt token, afterwards the token generated by the
previous step), records the greedy argmax of that position's logits as the
generated token and the BF16 residual stream after the last decoder layer
(before the final RMSNorm) as the hidden state. There is no early stop at
EOS, no sampling, and no repetition penalty.

Outputs: tokens (int64, [decode_steps]) and hidden_states (BF16,
[decode_steps, 1024]).

Test corpus (seeded, all 24 layers in every case; "smoke" refers only to the
short prompts and step counts, not to a smaller model):
- V0: the historical prompt [1234, 5678, 9012], decode_steps 5;
- V1: one legal ID (sometimes 0 or 1), prompt length 1, decode_steps 1;
- V7: length 8 containing a boundary ID (0 or 248319) and a duplicate, decode_steps 5;
- V8: uniformly random legal IDs, length 1..8, decode_steps 1.
The claim covers the whole input domain above (P in 1..8, decode_steps in {1, 5}),
not just these samples.

Validation: the reduced CUDA of each role was accepted by matching that
role's own original implementation bitwise on every output leaf of the frozen
samples. The two roles were not required to agree with each other bitwise;
the proof relates both to the shared reference specification, not to each
other's bits.
